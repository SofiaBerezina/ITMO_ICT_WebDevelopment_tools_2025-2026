# Лабораторная работа 3: Docker, очереди и асинхронный парсинг

## Цель работы

Научиться упаковывать FastAPI приложение в Docker, интегрировать парсер данных с базой данных и вызывать парсер через API и очередь.

В рамках лабораторной работы было выполнено:

1. FastAPI приложение из лабораторной работы №1 упаковано в Docker контейнер
2. Парсер из лабораторной работы №2 вынесен в отдельный сервис
3. Добавлены два способа вызова парсера: синхронный (через HTTP) и асинхронный (через очередь Celery + Redis)
4. Настроен Docker Compose для оркестрации всех сервисов
5. Настроены периодические задачи через Celery Beat

## API Эндпоинты

### Синхронный вызов парсера

`POST /parser/parse`

Запрос:
```json
{
  "url": "https://www.python.org"
}
```

Ответ:
```json
{
  "message": "Parsing completed",
  "url": "https://www.python.org/",
  "title": "Welcome to Python.org",
  "task_id": 1
}
```

**Как работает:** Основное API отправляет HTTP-запрос к сервису парсера, ждёт ответа и возвращает результат.

---

### Асинхронный вызов парсера (через очередь)

`POST /parser/parse-async`

Запрос:
```json
{
  "url": "https://www.python.org"
}
```

Ответ:
```json
{
  "message": "Parsing task started",
  "task_id": "abc-123-xyz"
}
```

**Как работает:** Задача ставится в очередь Redis, Celery worker забирает её и выполняет в фоне. Ответ возвращается сразу, не дожидаясь завершения парсинга.

---

## Как работает парсер (parser_service)

1. Принимает POST-запрос с URL
2. Скачивает страницу через `requests`
3. Извлекает заголовок страницы через `BeautifulSoup`
4. Сохраняет новую задачу в PostgreSQL:
   - Заголовок: `Прочитать: [название страницы]`
   - Описание: `Спарсено с [url]`
   - Приоритет: `medium`
   - Статус: `pending`
   - Тип: `work`
   - Пользователь: `parser`
5. Возвращает JSON с результатом
